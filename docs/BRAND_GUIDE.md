# Pickora 品牌与视觉规范 (BRAND GUIDE)

本文档确立了 Pickora 的核心视觉规范、UI 结构和设计红线。旨在确保微信小程序的长期演进始终不脱离最初的东方纸本美学定位。

## 1. 核心视觉基因

*   **米白纸本感**：全局背景、卡片底色以米色、浅米黄为主，模拟宣纸/牛皮纸的温润质感。
*   **楷体 (Kai Font)**：系统内核心文本（大标题、选项、引言等）必须使用 `var(--font-kai)`，营造传统手写/印刷的书卷气。
*   **红印章元素**：关键状态（如首推、已定等）的徽章或标志需采用中国传统印章红，强化“落子无悔”的仪式感。
*   **铜色边线**：卡片边框、分隔线、标签边框使用低饱和度的黄铜色/褐金色，避免纯黑或冷灰色。
*   **六象签牌语言**：使用“象”、“局”、“签”等东方命理占卜概念的词汇，构建沉浸式的“轻娱乐、低风险选择辅助”心智。

## 2. UI 核心规则

### 2.1 形状与圆角尺度表
*   **标签（Chip）**：`999rpx`（胶囊形态，用于选项池、历史与示例、已去掉项等）。
*   **小按钮（Small Button）**：`14rpx - 16rpx`（如“恢复”、“删除”等辅助按钮）。
*   **主按钮（Primary Button）**：`14rpx - 18rpx`。
*   **卡片（Card/Box）**：`16rpx - 24rpx`。
*   **注意**：操作按钮严禁使用胶囊形态，以便与标签（Chip）形成明确区分。

### 2.2 色彩与层级
*   **红色使用边界**：
    *   红色不能用于大面积普通提示。
    *   错误/空状态优先使用浅米红底 + 低饱和边线。
    *   危险操作（如“删除”）必须小面积、低权重。
    *   红色主要保留给结果页首推卡片高亮及“已定”等印章视觉。
*   **操作按钮层级**：
    *   “删除”、“恢复”等属于辅助操作，严禁占据大面积纯色块或半行宽度，必须小巧（如宽 `120rpx`，高 `52-56rpx`），靠右对齐。
    *   页面主视觉必须留给核心内容（如选项文本本身）。

### 2.3 结果页排版
*   **首推的绝对统治力**：结果页的首推卡片必须是视觉中心，拥有最强烈的样式表现。
*   **支撑信息的退让**：选项池、六象池、推荐权重列表作为支撑信息，视觉上必须次于首推卡片，不能喧宾夺主。

## 3. 设计红线与工程边界

### 3.1 视觉红线
1.  **不把品牌词普通化**：禁止将“极速起局”改为“二选一”、“六象池”改为“符号池”等。
2.  **不改成普通表单工具**：禁止引入常见的扁平化 SaaS 样式组件（如标准蓝色按钮、蓝色 Checkbox、大面积灰色背景等）。
3.  **不引入现代扁平风格**：不可丢弃楷体、米白纸本背景和铜色边线。
4.  **不恢复 Preview 环境**：所有 UI 和交互必须在原生微信小程序开发工具及真机下验收，不再依赖/构建本地浏览器 Web Preview 版本。
5.  **不新建浏览器 UI 镜像**：禁止为了方便审查而单独搞一套浏览器 UI，双端维护成本极高且易导致两端样式割裂。

### 3.2 工程边界
1.  **不使用 WXSS 掩盖 TS 状态机问题**：如果遇到逻辑错误，不要试图用 CSS 隐藏它。
2.  **优先检查状态机**：页面误跳转、结果闪烁、缓存残留、错误回退应优先检查 `index.ts` 状态机。
3.  **逻辑与视觉分离**：不把 core 算法修改混入 UI 或品牌视觉修复中。
