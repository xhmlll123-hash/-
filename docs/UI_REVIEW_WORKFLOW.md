# UI 审查流程

本文档定义 Pickora 后续 UI 修改和验收流程。删除浏览器镜像后，所有 UI 判断以真实微信小程序为准。

## 基本原则

- 不再新建 preview 或任何浏览器 UI 镜像。
- 不使用 DevTools 自动截图作为默认流程，不维护自动截图脚本。
- 截图基准以微信开发者工具中的人工真实截图为准。
- 截图文件如果要归档，必须人工确认后手动放入 `docs/screenshots/miniprogram/`。
- 不按浏览器 DOM 或浏览器 CSS 机械还原小程序 UI。
- 每轮 UI 修改只处理一个页面或一个模块，避免全页盲改。
- 品牌词不得替换，包括：极速起局、常用签牌、推荐权重列表、权重、六象池、首推、落象。

## 每轮修改范围

每轮开始前先确认目标页面或模块，例如：

- 首页 hero 和常用签牌
- 编辑页输入区和候选 chip
- 结果页首推卡片和支撑信息
- 选项库列表
- 长文本 chip

不在同一轮混合处理多个无关页面。

## 问题分层判断

每轮修复前先判断问题属于哪一层：

- WXML：结构顺序、条件渲染、缺失容器。
- WXSS：布局、间距、颜色、层级、按钮大小、chip 样式。
- TS：页面状态机、路由、点击逻辑、定时器、setData、缓存清理。
- core：推荐算法、权重规则、会话生成规则。

不要用 WXSS 掩盖 TS 状态机问题。
不要把 core 算法改动混入 UI 修复。

## 截图覆盖

每轮 UI 审查至少覆盖：

- 首页
- 编辑页
- 结果页
- 选项库
- 长文本 chip

如果自动截图不稳定，使用微信开发者工具人工截图作为验收依据。

## 每轮必须输出

每轮 UI 修改结束时必须提供：

- 修改文件
- 修改模块
- `npm run typecheck` 结果
- 微信开发者工具编译结果
- 真实截图待确认项

示例：

```text
修改文件：
- miniprogram/pages/index/index.wxml
- miniprogram/pages/index/index.wxss

修改模块：
- 编辑页候选项输入区
- 本轮选择池 chip

npm run typecheck：
- 通过

微信开发者工具编译结果：
- 已编译通过 / 未验证，原因：...

真实截图待确认项：
- 编辑页首屏
- 长文本 chip
```

## 禁止事项

- 不恢复 preview。
- 不新增浏览器镜像。
- 不机械同步浏览器样式。
- 不改品牌词。
- 不做全页盲改。
- 不为 UI 问题改核心算法。
- 不把截图产物、构建产物或本地缓存提交到 Git。

## 推荐顺序

优先从真实截图中最影响主流程的模块开始：

1. 编辑页输入区、候选 chip、主按钮。
2. 首页 hero、极速起局、常用签牌。
3. 结果页首推卡片、操作按钮、支撑信息。
4. 选项库。
5. 长文本和边界状态。
